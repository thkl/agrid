Chapter 2

How to configure columns

Static column definitions establish defaults. The control stores each user's runtime visibility, order, width, and pinning choices. 

{{ columnsGuideCode }}
  • Use locked for structural columns users must not move or hide.
  • Use showSidebar to expose a visibility selector.
  • Use headerGroups to label adjacent presentation columns.
  • Persist runtime choices with the settings API from Chapter 9.
Chapter 3

How to edit, validate, and save rows

Cells are editable by default. Disable editing per column or row, provide fixed values for select editors, and reject invalid commits with a message. 

{{ editingGuideCode }}
cellEditOne committed cell change, paste, fill, undo, or redo.
rowChangedThe latest complete row after navigation leaves it.
validationFailedThe rejected value, message, row, and edit source.

Use showChangedCellIndicator while a save request is pending, then call clearChangedCells() after the backend confirms success.

Chapter 4

How to select, copy, paste, and fill

Row selection and spreadsheet-style cell ranges are independent. Configure row selection on the provider; cell selection, keyboard copying, pasting, and fill handles work without additional setup. 

{{ selectionGuideCode }}
  • Shift+click or Shift+arrow extends a cell range.
  • Ctrl/Cmd+C and Ctrl/Cmd+V use tab-separated clipboard text.
  • The fill handle repeats a value or pattern down or right.
  • Row marking creates a persistent copy basket independent from selection.
Chapter 5

How to group and aggregate

Mark dimension columns as groupable and value columns with an aggregate. Aggregates appear in the footer and automatically become subtotals when grouping is active. 

{{ groupingGuideCode }}
Built-ins are sum, avg, min, max, and count. Column definitions may also provide a custom function.
Chapter 6

How to build a pivot table

A pivot converts flat source records into a read-only cross-tabulation. Choose one row dimension, one column dimension, one value field, and one aggregate. 

{{ pivotGuideCode }}
ReactiveDatasource updates immediately rebuild the matrix.
ConfigurableThe Pivot sidebar changes dimensions and visible columns.
PersistableSave pivot and column settings as one JSON object.

Pivot mode remains sortable, filterable, selectable, and pageable. Generated cells are intentionally read-only because they do not map to one source record.

Chapter 7

How to display tree data

Keep source rows flat and describe the hierarchy with parent IDs, or derive display-only branches from path segments. Editing and selection continue to use datasource indices. 

{{ treeCode }}
  • keepAncestorsOnFilter reveals the path to matching descendants.
  • aggregateTreeNodes rolls aggregate columns up from descendant leaves.
  • Use expandAllNodes() and collapseAllNodes() for bulk control.
Chapter 8

How to paginate and load server data

Use a page size when all rows are local. Use AgridServerSideRowModel when the dataset must be fetched in blocks and filtered or sorted by the backend. 

{{ paginationGuideCode }}
Local pagesThe control slices filtered rows automatically.
Remote pagesSet totalRows and respond to page/filter/sort events.
Lazy blocksThe server row model caches viewport-sized blocks.
Chapter 9

How to save and restore user settings

Save one versioned object containing pivot configuration and control state. The snapshot is detached and JSON-safe, so it can be sent directly to a backend. 

{{ settingsGuideCode }}

Settings include visibility, widths, order, pinning, filters, sorting, pagination, aggregates, and pivot configuration. Rows, selection, loading state, and edit history are intentionally excluded.

Custom aggregate functions are executable code and cannot be serialized. Register those in application code; save only built-in aggregate names.

Marking rows for copy

Row marking is independent from row selection. Enabling it adds a 48 px control column containing a checkbox and the existing menu or reorder handle. 

{{ rowMarkingCode }}
  • Copying a cell appends the same field from every marked row.
  • Copying a range appends the same column range from every marked row.
  • Copy row appends every visible field from every marked row.
  • Rows already present in the active copy selection are not duplicated.
  • Marked rows remain included when filters hide them.

Dynamic options

control.loading, control.readonly, and control.autoAddRows are readonly signals. Update them through setLoading(), setReadonly(), and setAutoAddRows().

Grouped column headers

{{ headerGroupsCode }}

The grouped-header row appears only when a visible column references a configured group. Adjacent columns with the same group ID share one header. Reordering, hiding, or pinning can split the same group into multiple contiguous headers, including separate headers in pinned panes.

  • Dragging a grouped header moves every column in that rendered segment together.
  • The columns keep their internal order while the segment moves.
  • A segment containing a locked column cannot be dragged.
  • group controls header presentation; groupable controls data-row grouping.
ISO date strings and Date objects are automatically formatted and sorted chronologically. A custom formatter takes precedence.

Aggregates and group subtotals

A column's aggregate (sum, avg, min, max, count, or a custom (values) => unknown function) renders a footer total over all filtered rows; toggle it at runtime with control.setAggregate(field, fn). When the grid is grouped, every group header row also shows that group's subtotals — the same functions applied to just the group's rows, inline beside the label and count. Subtotals appear automatically whenever grouping and at least one aggregated column are both active.

Filtering, typed columns, and validation

Column conditions and boolean columns

Mark a column filterable and its column menu gains a condition filter beside the value picker. Text columns offer equals, not equal, like, starts with, ends with, includes, and does not include. Numbers offer =, ≠, >, ≥, <, ≤, and between; dates offer on / before / after / between. A boolean column renders an inline checkbox that toggles the value on click — no edit mode — and the change goes through undo/redo like any other edit. 

{{ typedFilterCode }}

The condition combines with the value picker and other columns using AND semantics and is included in AgridControl.toJSON() state.

Quick filter

Set enableQuickFilter: true to render a search box above the grid that keeps rows whose visible columns contain the text. Matching uses resolved display values, so ValueOption labels and formatters count. 

{{ quickFilterCode }}

Server-side filtering

With serverSideFiltering: true the grid never filters locally — it emits events so the host can refetch. Text filters emit { field, value }; menu conditions add operator, operand, and operand2; the quick filter emits its text through quickFilterChange. All three are debounced by filterDebounceMs (default 300 ms). 

{{ serverSideCode }}

Edit validation

Add a validate hook to a column to reject bad values. Return a message to block the edit — the value is not written and the message is shown — or null to accept it. It runs on inline commit, boolean-checkbox toggle, and sidebar save. 

{{ validationCode }}
  • A rejected inline edit keeps the cell in edit mode with the message beneath it; Tab/Enter will not leave the cell until the value is valid.
  • Rejected sidebar edits show the message under the field.
  • Listen to (validationFailed) for { rowIndex, field, value, message, source }, where source is 'inline' or 'sidebar'.

Tree data

Set treeConfig on the provider to render rows as a hierarchical tree. The hierarchy is expressed over the existing flat row array using either stable id/parent-id accessors or a path accessor. The designated treeField column shows an indented expand/collapse twisty.

Tree mode can be combined with masterDetail: true and a detailRenderer. Detail expanders are shown only for leaf rows; parent rows retain their tree expand/collapse control. 

{{ treeCode }}
PropertyRequiredDescription
getIdParent modeReturns a stable, unique id for a row.
getParentIdParent modeReturns the parent row's id, or null for a root.
getPathAlternativeReturns ordered path segments and creates display-only branch nodes.
nodeUuidNoReturns the UUID included on generated branch nodes and branch-node click events.
formatPathSegmentNoFormats labels using the segment, path, level, leaf flag, and source row without changing identity or sorting.
treeFieldYesField whose cell shows the indentation and twisty.
defaultExpandedNoExpand all nodes on first render. Defaults to false.
keepAncestorsOnFilterNoKeep ancestors of filter matches visible. Defaults to true.
aggregateTreeNodesNoDisplay aggregate-column rollups from descendant leaves.

Path example: getPath: row => row.oz.split('.') renders 01.01.0001 as 01 / 01 / 0001. Only the leaf is a datasource row; generated branch nodes cannot be edited or selected. Use formatPathSegment to append labels while keeping raw segments for grouping and sorting. Shared branch nodes receive the first row encountered for their raw path prefix; nodeUuid uses that same row.

  • A row whose parent id is null or missing from the data renders as a root.
  • Filtering, sorting, and the column filter UI work the same as in a flat grid; siblings follow the active sort.
  • With keepAncestorsOnFilter (default), a match deep in the tree keeps its parents visible and force-opens the path to it.
  • Tree mode takes precedence over grouping and disables pagination.
  • Call expandAllNodes() / collapseAllNodes() on the component to expand or collapse the whole tree.
Tree mode keeps the data source flat, so the same indices drive cell editing and row selection. Use the parentId shape rather than nesting child arrays.

Saving a complete row

Use rowChanged when several field edits should become one API request. Moving between cells in the same row does not emit it. The event fires when navigation enters another row, filter focus clears the active cell, focus leaves the grid, or the sidebar Save button is used. 

{{ saveRowCode }}

Enable showChangedCellIndicator on the provider to display a corner marker after each committed change. Call clearChangedCells(event.originalIndex) only after the request succeeds. You can also clear selected fields or every marker.

Adding defaults in repeated grids

Use the provider and datasource carried by the event. This avoids coupling the event to the surrounding loop index.
